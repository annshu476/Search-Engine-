# Distributed Search Engine Frontend

This is a modern, fast, portfolio-quality Next.js (App Router) user interface for the Distributed Search Engine. It features technical styling, keyboard navigation, autocomplete suggestions, deep query filters, and comprehensive error handling.

## Requirements

* **Node.js**: `v20.x` or higher
* **npm**: `v10.x` or higher
* **Backend Dependency**: The Indexer service must be running at `http://localhost:8083`.

## Getting Started

1. **Install Dependencies**
   ```bash
   cd frontend
   npm install
   ```

2. **Configure Environment Variables**
   Create a `.env.local` file in the `frontend` folder (or set shell environment variables):
   ```env
   # Public Base URL pointing to the Indexer service
   NEXT_PUBLIC_API_BASE_URL=http://localhost:8083
   ```

3. **Run the Development Server**
   ```bash
   npm run dev
   ```
   Open [http://localhost:3000](http://localhost:3000) in your browser.

4. **Run Unit and Component Tests**
   ```bash
   npm run test
   ```

5. **Build for Production**
   ```bash
   npm run build
   ```

## Architecture Details

### Next.js API Route Proxies
Because the Indexer service does not have CORS enabled, the frontend implements a **Server Proxy** pattern using Next.js **Route Handlers**:
* `GET /api/search` proxies to `http://localhost:8083/api/search`
* `GET /api/suggest` proxies to `http://localhost:8083/api/search/suggest`

This allows browser-side JavaScript to make requests to the same origin (port 3000) avoiding any CORS block, while the Next.js server resolves the upstream connection to port 8083.

### Type Safety & DTO Integration
All APIs integrate with the Java Indexer records directly. Types are strictly defined in `src/types/search.ts`.

### Secure Highlight Parsing
Matched queries contain `<em>...</em>` tags generated by Elasticsearch. Instead of using unsafe `dangerouslySetInnerHTML`, the frontend parses highlight fields safely into structured React elements to prevent Cross-Site Scripting (XSS) issues.
